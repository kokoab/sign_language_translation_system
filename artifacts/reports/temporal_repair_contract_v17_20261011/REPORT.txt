Native input experiment
Ten source events: six approved MY, one ASLLRP HAVE, one ASLLRP LIKE, two phone
failure development events. Each starts a fresh production Vision/tracker stream
at source start, using true presentation timestamps, 20 Hz deadline sampling,
aspect-preserved video, the pinned FP16 hand encoder and production span builder.
Eight auxiliary phases × three capture offsets × three context views = 72 per
event. 720/720 views constructed; all arrays finite, validity masks binary, retained
core has >=2 hand frames and >=1 valid sampled crop position. These are 10 events,
not 720 independent examples. Encoders ran; word/letter/boundary classifiers did not.

At fixed capture offset and base context, auxiliary phase generated 6–8 distinct
landmark tensors per event, while hand-image embeddings were identical across the
eight phases. Thus shifting input phase is a real landmark variation, not merely
copying identical training arrays. No claim is made that phase training has already
fixed classification. This native macOS extraction pilot is not a normal-iPhone
accuracy/latency/thermal test. An initial 432-view run was repeated with retained-core
instrumentation; the authoritative results are pilot_inputs_v2 plus recovered_my_inputs.
