Clean-lineage recovery experiment — 2026-10-11

RESULT: completed; no replacement accepted or installed.
The proposed clean-model recovery improves MY and HAVE on some recordings, but
does not repair MY reliably and loses other vocabulary. The bounded retraining
and temporal inference experiment do not clear that failure. Production Python,
iOS sources, and the installed guarded-rollback app remain unchanged.

What was built and measured

1. Existing older clean-split interval recognizer, with a newly matched corrected
   A–Z/NONE head and FP16 Core ML export. The frozen base checkpoint is
   canonical_recognition_comparison_v17_20261007/downstream_recipe/august/
   span_recognizer/best_model.pth. This is NOT the original leaking LocalA model.
2. Continuous word decoding through NAME mode. Only letter state restarts; word
   evidence survives the mode switch. Word/letter caches are separate because
   their frame-index origins can differ. Delayed merged output sorts by sign
   start time. Existing one-way HAVE/ANGRY shape and TIRED roll guards remain.
3. The same runtime with the existing HAVE contact-preservation rule restored.
4. A class-independent three-view word probability average: normal window,
   earlier onset, shorter release. Original letter logits retained. No MY/LIKE
   swap, per-class threshold or additional fallback model is enabled.
5. Six-epoch frozen-encoder fusion-head continuation, then its own matched
   corrected letter head/export. Both visual encoders are tensor-identical to
   the clean base; all14fusion-head tensors changed. Epoch1 selected.

Interpretation and next repair

The model lineage change is a real contributor, and the temporal runtime is a
separate contributor. The controlled results do not establish which one October
training change caused all representation drift. Restoring the older clean
lineage is insufficient; merely retaining word state, increasing auxiliary
cadence, averaging windows or continuing the same head recipe is insufficient.

The next training experiment needs a reviewed input contract that actually
covers the missing continuous behavior: verified short MY/LIKE cores, HAVE
contact followed by BIG, release motion, and native sampling-phase variants.
Start from the reconciled existing-source inventory, preserve original gloss
variant identities and split exclusions, and treat all derived windows of a
video as one source. Do not label the mixed phone recording from its model
predictions or call a repeatedly tuned phone recording an independent test.
Pin a separate untouched phone evaluation session before candidate selection.

Use the current vocabulary behavior as a retention target; compare against the
older clean model rather than replacing the whole model blindly. Test a small
matched adaptation only after the reviewed spans/input recipe exists, with
per-class retention, complete phrase outputs, every sampling phase, genuineLIKE
controls and normal loaded-phone performance as promotion gates. Reuse the
continuous-state/trace changes as separately evaluated runtime components.
The existing one-way geometry/roll guard remains a useful cue; the earlier
direct MY geometry sweeps already harmed trueLIKE and are not revived here.
This is a concrete next experiment, not a claim that an untested recipe will fix it.
