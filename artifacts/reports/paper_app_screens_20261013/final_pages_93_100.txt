4.4 Implementation Plan (Infrastructure/Deployment)


4.4.1 Implementation Overview


          The implementation plan concerns ATLAS: A Squeezeformer-Based System

for Sign Language Recognition and English Translation. Its purpose is to integrate the

selected recognition and English-generation components into a mobile application

that captures signing, maintains accepted glosses and presents English text and local

speech.

          Implementation covers model preparation, application integration, device

deployment and evaluation. Its objectives are to preserve recognition behavior after

conversion, connect the processing components correctly, provide the intended

application functions and document performance under the stated evaluation

conditions. The implementation schedule follows the activities identified in the

project GANTT and PERT charts.


4.4.2 Model and Application Deployment

          The trained neural components are exported for on-device inference. FP32

uses 32-bit floating-point values, while FP16 uses 16-bit values. The selected

configuration uses FP16 visual and recognition components and retains FP32 for

English generation. The deployment evaluation examines recognition performance,

model storage, and processing time. Figure 16 summarizes how the component

comparisons inform these engineering choices.

        ATLAS brings together four neural components with different responsibilities:

image encoder and T5-efficient-tiny. The boundary model estimates candidate sign

timing, while the recognizer determines which signs those intervals contain.

MobileCLIP2 supplies hand-appearance features that complement landmark motion,

and T5-efficient-tiny turns the accepted gloss sequence into English. These

components connect visual recognition with sentence generation, but they are not a

single trained model.
